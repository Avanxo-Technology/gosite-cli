# __PROJECT__

A gosite **thin site**: Go + Cockpit CMS. The core — CMS client, page cache,
SEO, analytics, consent, purge — is the Go module in `go.mod`, not code in this
repository. Its contract is `CORE_API.md` in that module.

## Where things go

| You want to… | Edit |
| --- | --- |
| add a page or route | `site/` (register it in `Routes`) and `theme/pages/` |
| change markup or styling | `theme/`, `static/` |
| change what core renders (consent link, SEO tags…) | define the same template name in `theme/components/` |
| add Redis data that is not cache | `r.State()` — never raw keys under the project prefix |
| enable an addon | `gosite addons add <Name>` (edits `gosite.yml`) |
| change a Cockpit setting | `cockpit/config.local.php` |
| change the dev stack | `docker-compose.override.yml` |
| change ports, domains, storage | `gosite.yml`, then `gosite generate` |

## Rules

- **Never copy core code into this site** — no `internal/cms`, no own cache, no
  vendored core. If core lacks something, it belongs in gosite, not here.
- **Read content only with `r.CMS()`.** No MongoDB driver, no direct queries.
- **Serve CMS pages with `r.CachedRender`** so a publish reaches them via purge.
- **Keep the three slots** in `theme/layout.html`, each called once:
  `gosite:head`, `gosite:body-start`, `gosite:body-end`. `go test ./...` checks.
- **Do not edit generated files** — the ones whose first lines say
  "generated by gosite generate": the compose files, `deploy/`,
  `cockpit/config.core.php`. Use the override next to each.

## Upgrading core

Change the version in `go.mod` (and `core:` in `gosite.yml`), `go mod tidy`,
`gosite generate`, `gosite restart __PROJECT__ --build`. No merge.
