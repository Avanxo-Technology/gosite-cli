## ADDED Requirements

### Requirement: Client identity behind a reverse proxy

The Forms addon SHALL derive the submitting client's IP address in a way that is correct when the CMS runs behind a reverse proxy, and that cannot be spoofed by the client.

The number of trusted proxy hops SHALL be an explicit configuration value (`config/forms/trustedProxies`, an integer, default `0`). When it is greater than zero, the address SHALL be taken by counting that many entries from the **right** of `X-Forwarded-For`, never from the left.

The project scaffold generated by gosite SHALL ship `trustedProxies: 1`, because every gosite project sits behind exactly one Traefik hop.

#### Scenario: Direct connection, no proxy configured

- **WHEN** `trustedProxies` is `0` and a submission arrives
- **THEN** the client identity is `REMOTE_ADDR`
- **AND** any `X-Forwarded-For` header present in the request is ignored

#### Scenario: Single trusted proxy

- **WHEN** `trustedProxies` is `1` and a request arrives with `X-Forwarded-For: 203.0.113.9`
- **THEN** the client identity is `203.0.113.9`

#### Scenario: Client attempts to spoof its address

- **WHEN** `trustedProxies` is `1` and a client sends `X-Forwarded-For: 1.2.3.4` which Traefik appends to, producing `X-Forwarded-For: 1.2.3.4, 203.0.113.9`
- **THEN** the client identity is `203.0.113.9`
- **AND** the client-supplied `1.2.3.4` is discarded

#### Scenario: Fewer entries than trusted hops

- **WHEN** `trustedProxies` is `2` but `X-Forwarded-For` carries a single entry
- **THEN** the client identity falls back to `REMOTE_ADDR`

#### Scenario: Two distinct visitors are rate limited independently

- **WHEN** two visitors with different public IPs submit the same form through the proxy within the throttle window
- **THEN** both submissions are accepted
- **AND** neither consumes the other's quota

### Requirement: Rate limiting fails closed

The anti-spam layer SHALL reject a submission when it cannot evaluate the rate limit. A failure of the memory backend MUST NOT result in an unlimited request path.

#### Scenario: Memory backend unavailable on read

- **WHEN** the memory backend throws while reading the throttle counter
- **THEN** the submission is rejected with HTTP 503
- **AND** the response body carries a retriable error message
- **AND** the failure is logged

#### Scenario: Memory backend unavailable on write

- **WHEN** the counter is read successfully but the subsequent write throws
- **THEN** the submission is rejected with HTTP 503
- **AND** no submission document is persisted

#### Scenario: Rate limiting explicitly disabled

- **WHEN** both `throttle` and `dailyLimit` are configured as `0` for a form
- **THEN** the submission is accepted without consulting the memory backend

### Requirement: Public receiver restricts cross-origin access

The public submission endpoint SHALL NOT emit `Access-Control-Allow-Origin: *` unless an operator has explicitly configured `*` as an allowed origin.

When `config/forms/allowed_origins` is unset, the endpoint SHALL reflect no origin and the scaffold SHALL document how to configure it.

#### Scenario: Allowed origins not configured

- **WHEN** `allowed_origins` is absent from the configuration and a cross-origin request arrives
- **THEN** no `Access-Control-Allow-Origin` header is emitted

#### Scenario: Request origin is on the allow list

- **WHEN** `allowed_origins` contains `https://www.example.com` and a request arrives with that `Origin`
- **THEN** `Access-Control-Allow-Origin: https://www.example.com` is emitted
- **AND** `Vary: Origin` is emitted

#### Scenario: Wildcard explicitly opted into

- **WHEN** an operator configures `allowed_origins` as `['*']`
- **THEN** `Access-Control-Allow-Origin: *` is emitted

#### Scenario: Same-origin form post still works

- **WHEN** a form is posted from the CMS's own origin with no `Origin` header
- **THEN** the submission is processed normally regardless of the allow list
